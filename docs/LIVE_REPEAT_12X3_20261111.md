# November 11, 2026: 12-Tool Live Repeatability Pilot

A new and separately authorized Geoapify MCP run covered all **12 tools in the observed MCP catalogue**, with **three non-identical inputs per tool** (36 actual `tools/call` requests). This supplements, and does not replace, the historical LIVE-FB-10 and R1-PILOT-01 records.

## Results

| Measure | Verified observation |
| --- | --- |
| Actual MCP tools/call attempts | 36 |
| Tool-level successful exchanges | 36/36 |
| Initial internal functional smoke checks | 33 PASS / 3 UNKNOWN / 0 FAIL |
| Original UNKNOWNs | All three `get_timezone` results, unsupported by the then-current normalization adapter |
| Geocode → reverse-geocode dependencies | 3/3 downstream arguments linked to the same run's real upstream coordinates |
| Stored response SHA256 checks | 36/36 |
| Internal private file inventory | 77/77 SHA256 matches (only inventoried files) |
| Credits locally reserved | 42.0; hard ceiling 60 |
| Credits actually billed by provider | Unknown (not observed) |
| Temporary authorization | Revoked after the run |
| External independent geographic truth | Not established |

The three time-zone responses themselves contained the expected time-zone names and UTC offsets: Europe/Berlin (+01:00), America/New_York (-05:00), and Asia/Tokyo (+09:00). That confirmation was made by reading their real, stored structured-response fields. It did not reclassify their original adapter outcomes as PASS.

After the run, we implemented a narrowly scoped `get_timezone` normalization improvement. An **offline replay of the three original captured response payloads** returned 3/3 supported normalizations; two malformed synthetic time-zone examples were rejected. No additional provider calls were made for this fix. The public code contains the equivalent normalized time-zone capability and unit tests; raw provider responses and the private runtime remain outside GitHub.

**Evidence interpretation:** A successful tool call is not proof of a correct geographic answer. The functional checks cover basic schema integrity, bounded geographic plausibility, simple geometry expectations, limited route/matrix structure, and field lineage. They do not establish an independent geographic accuracy rate.

The pilot is **not** 18 formal benchmark tasks each executed three times. The original internal status remains NO_GO / REAL18 0/18 / G10 CLOSED / batch_2_authorized=false. No original sealed evidence was changed.
